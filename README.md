# sns-daily-digest

全 SNS 自動投稿（Threads・Instagram・X）の結果を見回り、**毎朝 7:30 にまとめを1通**、**失敗があればすぐに1通**、LINE で知らせる仕組み。

- **掛け合いリマインド**：キャラクター（ヘタ郎）の投稿が出たら、次の毎時の見回りで「公式アカウントからのコメント案」を媒体ごとに1通ずつ送る。予定は各リポジトリの `data/kakeai.json`（`feeds.json` の `kakeai`）。朝のまとめにも「今日の掛け合い」を載せる。コメントは本人が手で行う。
- **読むだけ**：各リポジトリの投稿記録と実行履歴を読むだけ。投稿・承認・設定の変更は一切しない。
- **見回る対象**：`feeds.json`（アカウントや媒体が増えたら1行足す）。
- **1日3本（2026-10-20〜）**：`feeds.json` の媒体に `slots: [{ slot, time }]` があると、その日の予定・記録に `slot` があれば枠ごとに数える（Threads：ハーレー 7:05/12:05/20:05、ZERO RIDERS 7:25/12:25/20:25、ヘタ郎 7:45/12:45/20:45、エンパワー 7:55/12:55/20:55。X：ハーレー 6:50/11:50/19:50、ロストボール 7:10/12:10/20:10、ZERO RIDERS 7:30/12:30/20:30、ヘタ郎 7:50/12:50/20:50、エンパワー 8:10/13:10/21:10）。Instagram は1日1本のまま。朝のまとめは「3本（7:05・12:05・20:05） 承認済み 3/3・1/3 投稿済み」。`slot` の無い予定（旧1日1本）の日は従来の表示。X は x-queue.json / x-posts.json の `date` と `slot`、エンパワー Threads は draft-bank.json の `targetDate` と `slot`、記録の `slot` / `targetDate`（旧は null）で数える。ヘタ郎の掛け合いは X が3本になっても1日1回（その日いちばん早い投稿）。
- **ロストボール Threads は1日4本（2026-10-20〜）**：日本語 朝7:35・昼12:35・夜20:35＋英語 夜21:00。朝のまとめは「4本（7:35・12:35・20:35・英語21:00） 承認済み 4/4・1/4 投稿済み」。同じ「夜」に日本語と英語があるので、`feeds.json` の枠に `lang`（ja / en）を書き、予定・記録の `lang` も一致するものだけをその枠として数える。`label: "英語"` は表示名。10/19までは従来どおり「Threads 5:00」。
  - 毎時の見回りは、枠ごとに「時刻 + 猶予（`graceMinutes`、既定30分）」を過ぎても記録が無いとき、その最初の見回りで1回だけ知らせる。後の枠・未承認の枠は知らせない。
  - 手元で試すとき：`FIXTURES_DIR=tests/fixtures/slots NOW=2026-10-21T07:30:00+09:00 node scripts/digest.mjs`（鍵が無いので送信せずログに出すだけ。`watch.mjs` は `SINCE` も使える）。
- **Googleビジネスプロフィール（エンパワー、毎日9:15、手で予約）**：API が無いので本人が Google の画面で予約し、記録を `threads-automation-empower` の `data/gbp-schedule.json` に書く（`feeds.json` の `gbp`。本文は書かない）。朝のまとめのエンパワー欄に「✅ Googleビジネスプロフィール 9:15 予約済み（〜10/19）」（今日が未予約なら ⚠️）。土曜・日曜は次の火〜月が全部予約済みになるまで「来週分の確認・承認日」、予約が明日までで切れそうなら警告（月曜は「明日の分がありません」）、承認済み・未予約の本数も【要対応】に載せる。記録が読めないときは「GBPの予約記録が読めません（未確認）」の1行だけ。毎時の見回りでは知らせない。
  - 手元で試すとき：`FIXTURES_DIR=tests/fixtures/gbp NOW=2026-10-17T07:30:00+09:00 node scripts/digest.mjs`
- **コメントの返信アシスト（半自動、2026-10-15〜）**：5アカウントの Threads・Instagram に来た新しいコメントを、毎時の見回り（`watch.yml`）で **LINE に1件ずつ**送る。AI（Gemini）の返信案を2〜3個つける。**自動では返信しない**（本人が選んで手で貼る）。
  - コメントを見つけるのは各リポジトリの `comment-watch.yml`（3時間おき 7:21〜22:21。ロストボールは毎時 6:27〜23:27）。中身は暗号化して `data/comment-inbox.enc.json` に置く。ここでは秘密鍵（`INBOX_PRIVATE_KEY`）で戻して読む。読む先は `feeds.json` の `commentInbox`（`tone`＝口調、`facts`＝言ってよい事実。ロストボールは `verified-facts.json` の確認済みだけ）。
  - 悩み相談・クレーム・攻撃的・個人情報・医療/法律/お金・福祉の利用者に関わる話などは「⚠️ 人が判断してください（理由）」で、返信案はつけない。
  - 1回の見回りで最大10件。多いときは「ほかにN件（次の見回りで送ります）」と1行送り、次の見回りで実際に送る。送る時刻は、コメントを見つけた時刻＋10分以降の最初の「:40」（5時台〜23時台）に1件ずつ割り当て、1つの :40 に10件まで。あふれたら次の :40 へ。毎時の見回りは「前回の開始〜今」に入る :40 の分だけ送るので、同じコメントを2回送らない（状態ファイルは持たない。`lib/comments.mjs` の先頭に説明）。見回りが抜けたときだけ、10件を超えた分を「送れませんでした」と件数で知らせる。
  - AI の鍵（`GEMINI_API_KEY`）が無いあいだは、コメントだけ送り「返信案はAIの鍵の登録後に付きます」。モデルは `gemini-3.5-flash-lite`（変数 `GEMINI_MODEL` で変更可）。
  - ログには件数だけ（コメント・名前・返信案は出さない）。
- **Mac で動く投稿（エンパワー LITALICO 6:00・note 5:55、2026-10-16〜）**：GitHub では動いていないので、Mac の `~/projects/mac-status-reporter/report_status.py` が実行のたびに結果を `threads-automation-empower` の `data/mac-status/`（`litalico-posts.json`・`note-posts.json`＝日付・状態・理由コード・公開タイトル・公開URLだけ。`*-planned.json`＝承認済みの日付だけ）に書く（`feeds.json` の LITALICO・note と `macStatus`）。
  - 朝のまとめ：公開（published）・手動で投稿済み（skipped）は「投稿済み」、止まった記録だけなら「止まりました」、記録が無ければ「予定あり・まだ出ていない」（Mac が寝ていた・動かなかったとき）。
  - 毎時の見回り：前回以降に「止まった・エラー」の記録が入れば、1件ずつ「【⚠️ LITALICO の投稿が止まりました】日付・理由（やさしい日本語）・対処」を1通。理由の言い換えは `lib/macstatus.mjs`。ログは件数だけ。
  - 手元で試すとき：`FIXTURES_DIR=tests/fixtures/macstatus NOW=2026-10-16T07:30:00+09:00 node scripts/digest.mjs`
- **時間**：まとめ 7:30 JST（`digest.yml`）／失敗の見回り 5:45〜23:45 JST の毎時（`watch.yml`）。
- **鍵**（GitHub Secrets。値はここに置かない）：
  - `GH_READ_TOKEN`：5つの自動投稿リポジトリを読むだけの鍵（Contents・Actions を Read-only）
  - `LINE_CHANNEL_ACCESS_TOKEN`／`LINE_TO`：LINE 公式アカウントから運用者本人へ送るための鍵
  - `INBOX_PRIVATE_KEY`：各リポジトリの暗号化されたコメントを戻すための秘密鍵（公開鍵は各リポジトリの `config/inbox-public.pem`）
  - `GEMINI_API_KEY`：返信案を作る AI の鍵
  - 登録は本人がターミナルで `node scripts/connect.mjs`（入力は表示されない。確認できたものだけ保存）
- 鍵が無いあいだは送信せず、ログに出すだけ（dry-run）。
- このリポジトリは公開（GitHub の実行時間の上限を避けるため）。ログに鍵や投稿本文は出さない。
